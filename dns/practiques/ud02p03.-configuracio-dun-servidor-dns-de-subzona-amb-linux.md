# 📎 AA-Q.3.3.4 - Servidor DNS de subzona amb Linux

## Objectiu

A partir de la zona pública **`nomcognom.netsx.es`**, ja publicada en AWS, es crea una subzona real:

```
sublin.nomcognom.netsx.es
```

La zona pare delega la subzona a una segona instància EC2 Ubuntu Server 24.04 amb BIND9. L'activitat mostra una infraestructura DNS jeràrquica funcional: el DNS pare no conté els registres de `sublin`; només publica l'NS i el _glue_ que permeten arribar al servidor fill.

## Abans de començar

Han d'estar operatius:

* el DNS autoritatiu públic de `nomcognom.netsx.es`, amb la seua Elastic IP;
* les regles AWS que permeten UDP/53 i TCP/53 al DNS pare;
* una segona EC2 Ubuntu Server 24.04 per a la subzona, amb una Elastic IP pròpia;
* les regles AWS que permeten UDP/53 i TCP/53 des d'Internet a la nova EC2.

Els valors `IP_PARE` i `IP_SUBLIN` s'han de substituir per les Elastic IP reals. El nom `nomcognom` es reemplaça pel nom assignat.

## 1. Delegar la subzona des del DNS pare

En la instància que serveix `nomcognom.netsx.es`, s'edita el fitxer de zona pare. S'afigen aquests dos registres:

```dns
sublin      IN NS dns1.sublin.nomcognom.netsx.es.
dns1.sublin IN A  IP_SUBLIN
```

* L'NS delega `sublin.nomcognom.netsx.es.`.
* L'A de `dns1.sublin` és el **glue**. És necessari perquè el nom de l'NS està dins de la subzona que s'està delegant.
* No s'afig un A de `www.sublin` al fitxer pare: eixe registre pertany al servidor fill.

S'incrementa la sèrie del SOA de la zona pare, es valida i es recarrega BIND:

```bash
sudo named-checkzone nomcognom.netsx.es /etc/bind/forward.nomcognom.netsx.es
sudo systemctl reload named
```

## 2. Configurar BIND9 en la EC2 Linux de subzona

En la instància nova:

```bash
sudo apt update
sudo apt install bind9 bind9-utils bind9-doc dnsutils
sudo nano /etc/bind/named.conf.options
```

Es configura com a servidor autoritatiu públic, sense recursió ni transferències:

```bind
options {
    directory "/var/cache/bind";
    allow-query { any; };
    allow-transfer { none; };
    recursion no;
    dnssec-validation no;
    listen-on { any; };
    listen-on-v6 { none; };
};
```

Si UFW està actiu, també s'obrin els dos protocols:

```bash
sudo ufw allow 53/udp
sudo ufw allow 53/tcp
```

## 3. Declarar i crear la zona filla

En `/etc/bind/named.conf.local`:

```bind
zone "sublin.nomcognom.netsx.es" IN {
    type primary;
    file "/etc/bind/forward.sublin.nomcognom.netsx.es";
    allow-update { none; };
};
```

Es crea `/etc/bind/forward.sublin.nomcognom.netsx.es`:

```dns
$TTL 300
@ IN SOA dns1.sublin.nomcognom.netsx.es. admin.nomcognom.netsx.es. (
    1 3600 600 1209600 300
)
@    IN NS  dns1.sublin.nomcognom.netsx.es.
dns1 IN A   IP_SUBLIN
www  IN A   IP_SUBLIN
@    IN TXT "Subzona Linux de NOM_COGNOM"
```

L'A de `dns1` del fill ha de coincidir exactament amb el _glue_ publicat al pare.

Es valida i s'inicia el servei:

```bash
sudo named-checkconf
sudo named-checkzone sublin.nomcognom.netsx.es /etc/bind/forward.sublin.nomcognom.netsx.es
sudo systemctl enable named
sudo systemctl restart named
```

## 4. Verificar la delegació

Des d'una altra instància o xarxa externa, es fan aquestes proves:

```bash
# Autoritat directa del fill per UDP i TCP.
dig @IP_SUBLIN sublin.nomcognom.netsx.es. SOA +norecurse +notcp +ignore
dig @IP_SUBLIN sublin.nomcognom.netsx.es. SOA +norecurse +tcp
dig @IP_SUBLIN www.sublin.nomcognom.netsx.es. A +norecurse

# Referència que proporciona el pare: NS i glue.
dig @IP_PARE www.sublin.nomcognom.netsx.es. A +norecurse

# Resolució normal a través de la jerarquia.
dig www.sublin.nomcognom.netsx.es. A
dig +trace www.sublin.nomcognom.netsx.es. A
```

Les consultes directes al fill han de mostrar `aa`. La consulta al pare sense recursió ha de retornar una referència amb l'NS en `AUTHORITY` i el _glue_ en `ADDITIONAL`. La resolució final ha de retornar l'A publicat pel fill.

També es comprova que no es pot transferir la zona:

```bash
dig @IP_SUBLIN sublin.nomcognom.netsx.es. AXFR
```

## 5. Lliurament

S'entreguen:

* Elastic IP del DNS pare i de la EC2 Linux de subzona;
* fragment de la zona pare amb NS i _glue_;
* declaració i fitxer de la zona `sublin.nomcognom.netsx.es`;
* captures del Security Group i del tallafoc local, si està actiu;
* evidències de UDP, TCP, referència del pare, resolució pública i AXFR denegat.

La zona inversa de l'Elastic IP no forma part de l'activitat: el PTR públic el controla AWS.
